# Runtime dependencies.
#
# Pinned to exact versions rather than floors. These are the versions the
# detector's accuracy was confirmed against, and two of them are load bearing
# in ways a range would not protect:
#
#   transformers  MERT is loaded through trust_remote_code, so the checkpoint
#                 carries code that expects a specific API. 4.45 moved parts
#                 of it and the load fails.
#   torch         weights are unpickled; the format is stable, but the ops the
#                 backbone lowers to are not, and a minor bump has changed CPU
#                 numerics before.
#
# A `>=` here means an image rebuilt six months from now runs a model nobody
# tested. Bump deliberately, re-run docs/testing.md against labelled audio, then
# commit the new pin.
#
# Install torch/torchaudio from the CPU index or pip resolves to the CUDA
# build (~2.5 GB against ~200 MB) even on a machine with no GPU:
#   pip install --extra-index-url https://download.pytorch.org/whl/cpu -r requirements.txt

# --- beat tracking ---------------------------------------------------------
# Installed from the archive because it is not published to PyPI under a
# version that matches upstream's current API.
#
# Written as a PEP 508 direct reference ("name @ url") rather than a bare URL.
# A bare URL is valid to `pip install -r` but NOT a parseable requirement, and
# pyproject reads this file for `dynamic = ["dependencies"]` - so the bare form
# made every wheel and `pip install -e .` fail with InvalidRequirement.
beat_this @ https://github.com/CPJKU/beat_this/archive/main.zip

# ONNX Runtime carries the two small Level-1 detectors (~1.2 MB of weights
# against Stage-1's 1.29 GB). 1.17 is a floor rather than a pin because the
# graphs are plain float32 and every release since has run them identically;
# it is also the first release with the INT8 MMLA and BF16 SGEMM kernels that
# make a Graviton3+ deployment worthwhile.
